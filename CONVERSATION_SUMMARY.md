# PierreScope Showcase — Conversation Summary

## Goal

Present PierreScope as a real AI-built Portfolio Intelligence Tool and make it easy for people to understand what its creator knows about AI and what has been built. The audience includes professional contacts, potential employers, and people discovering portfolio tools.

The intended path is LinkedIn profile/post → GitHub case study → interactive showcase.

## Positioning and proof

- Lead with “Built with AI. Designed for portfolio decisions.”
- Explain both AI-assisted product creation and AI capabilities within PierreScope.
- Show the product's broader Operations and Transformation capabilities with a concise visual overview, then map them to the four limited demo areas.
- The one-pager is the visual introduction, not the complete proof. The README adds a short product case study and a saved AI example with its evidence.
- Supported delivery approaches include AI-DLC, Scrum, Kanban, and Waterfall.

## Demo decisions

- Keep the showcase read-only and limited to four areas: Portfolio Overview, AI Examples, Planning & Capacity, and Data & Integrations.
- Use saved AI examples and evidence; the showcase makes no live model calls.
- Use synthetic demonstration records, names, and values. This describes the sample data only; PierreScope and its demonstrated capabilities are real.
- Show team-level capacity without a named resource roster. Do not imply live integrations or customer-configurable hosting.

## Privacy and release boundaries

- Keep the operational app and commercial core private.
- Exclude operational source, databases, credentials, customer records, actual work screenshots, personal resource details, internal configuration, prompts, mappings, scoring rules, and security internals.
- Do not announce commercial availability or a release date.
- Do not change licensing or copy an existing app license into this package.
- The static hosted showcase exposes its HTML, CSS, and JavaScript; it is only the intentionally limited public demo slice.

## Publishing direction

- Prepare one GitHub-ready repository named pierrescope-portfolio-intelligence with the case study and static showcase.
- Use GitHub Pages from the repository root by default, or upload the same static files to a standard website host. Include a README, one-pager, integration diagram, reviewed screenshots, transfer guide, and LinkedIn post draft.
- Add the one-pager and links to the GitHub repository and hosted showcase to LinkedIn.
- Hosting and publication remain a user-controlled step after reviewing the export.

## Transfer workflow

1. Copy the ZIP to another machine and extract it.
2. Review README.md and this summary, then create an empty public GitHub repository.
3. Copy the package contents into the repository, commit, and push to main.
4. Enable GitHub Pages from the main branch and repository root, or upload the unzipped static files to a standard host web root.
5. Verify the HTTPS site, four showcase areas, chart, image assets, and saved AI evidence.
6. Update the README and LinkedIn draft with the final repository and Pages URLs before sharing.
